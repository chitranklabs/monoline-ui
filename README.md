# Monoline UI

[![Release](https://img.shields.io/npm/v/@chitrank2050/monoline-ui?color=black&style=flat-square)](https://www.npmjs.com/package/@chitrank2050/monoline-ui)
[![License](https://img.shields.io/npm/l/@chitrank2050/monoline-ui?color=black&style=flat-square)](https://github.com/chitranklabs/monoline-ui/blob/main/LICENSE)
[![Build Status](https://img.shields.io/github/actions/workflow/status/chitranklabs/monoline-ui/ci.yml?branch=main&style=flat-square)](https://github.com/chitranklabs/monoline-ui/actions)

Monoline UI is a monochrome-by-default, layout-focused React design library and Next.js documentation playground.

It is designed to be extremely lightweight, performant, tree-shakeable, and fully compatible with **React 19**, **Next.js (App Router)**, and **Tailwind CSS v4**.

---

## Business Outcome & Rationale

> [!TIP]
> **Why Monoline UI?**
> Developer sites, personal portfolios, and documentation playgrounds should not be bogged down by heavy, non-tree-shakeable UI packages or duplicate dark-theme class gymnastics. Monoline UI guarantees high-performance rendering (0kb client JS overhead for static sections) and unified, token-driven customization.

---

## Repository Architecture (Flat-Library)

Monoline UI uses a flat single-package architecture (eliminating pnpm workspace sync overhead):

- `/app` is the Next.js playground and documentation site.
- `/src` is the source code of the UI library.
- `/dist` is the compiled production package (generated by compiler scripts).

```text
monoline-ui/
├── app/                         <-- Next.js Playground / Documentation App
├── src/                         <-- Core UI Library Source
│   ├── components/              <-- UI Components (e.g. Footer)
│   │   └── footer/
│   └── foundations/             <-- Theme CSS layers, tokens, breakpoints
├── scripts/
│   └── build-lib.mjs            <-- Library ESM bundling script
├── package.json                 <-- Unified dependencies & scripts
└── tsconfig.json                <-- Compiler paths mapping configuration
```

## Technical Specification

- **Runtime Target**: Node.js `>=22.0.0`
- **Package Manager**: pnpm `>=10.0.0`
- **Core Compiler**: TypeScript 6.0 (Targeting ES2022 / Bundler module resolution)
- **Styling Pipeline**: PostCSS with `@tailwindcss/postcss` v4
- **Dependencies**:
  - `@radix-ui/react-slot`: Polymorphic render delegation (0kb client runtime impact when static)
  - `clsx` & `tailwind-merge`: CSS class composition helper
  - `next` and `react` (v19 peer dependencies)

## Consumer Setup & Integrations (React 19 Ready)

### 1. Tailwind CSS v4 Configuration

In the consumer's root stylesheet (e.g., `app/globals.css`), import Tailwind and point its compiler to the Monoline library files under `node_modules` so that only the used styling classes are bundled:

```css
@import "tailwindcss";

/* Scan Monoline UI compiled outputs to generate only used Tailwind utilities */
@source "node_modules/@chitrank2050/monoline-ui/dist/**/*.{js,mjs}";

/* Import the Monoline design tokens and variables */
@import "@chitrank2050/monoline-ui/theme.css";
```

### 2. Composable Dot-Notation & React Server Components (RSC)

> [!IMPORTANT]
> Our composite components are Server Components by default. Interactivity is isolated to specific subcomponents, resulting in **0kb client-side hydration cost** for static layouts:

```tsx
import { Footer } from "@chitrank2050/monoline-ui/components/footer"

export default function MyFooter() {
	return (
		<Footer size="md">
			{/* Renders statically on the server */}
			<Footer.Status>Available for contracts</Footer.Status>

			{/* Handles client actions natively */}
			<Footer.Subscribe action={subscribeFormAction} />
		</Footer>
	)
}
```

### 3. React 19 Server Actions (Zero Client-Side JavaScript)

Since `<Footer.Subscribe />` compiles on the server, you can pass standard async **React 19 Server Actions** directly to the `action` prop. Form submissions run securely on the server with zero client JS requirements:

```typescript
// app/actions.ts
"use server"

export async function subscribeFormAction(formData: FormData) {
	const email = formData.get("email")
	await db.newsletter.create({ data: { email } })
}
```

### 4. Link Polymorphism (`as` / `linkComponent` / `asChild`)

To support SPA client-side routing (like Next.js `next/link` or Remix `Link`), Monoline UI supports three levels of component polymorphism:

#### A. Global Link Wrapper

Pass your routing component once to the parent `<Footer />` to override all links internally:

```tsx
import Link from "next/link"
;<Footer linkComponent={Link} columns={myColumns} />
```

#### B. Link-level Override

Override individual links dynamically inside the config array:

```tsx
import Link from "next/link"

const columns = [
	{
		title: "Navigate",
		links: [
			{ label: "Blog", href: "/blog", as: Link }, // Prefetches automatically
			{ label: "Twitter", href: "https://x.com", external: true }, // Standard anchor
		],
	},
]
```

#### C. Composable Subcomponent

If writing custom footer structures, render using `Footer.Link` with the Radix-powered `asChild` prop:

```tsx
import Link from "next/link"
;<Footer.Link asChild>
	<Link href="/about">About me</Link>
</Footer.Link>
```
